## 摘要

构建分层 agent 经济：底层是大量 agent 在半模拟环境中执行真实有用任务（数据标注、推理验证、知识整理）；其产出的一部分自留，一部分以"能量地租"形式上缴协议层；全程 kWh 记账、x402 微支付结算、区块链确权。必须内置自愿参与、可退出、收益分成的伦理设计——否则就是"带更多步骤的奴隶制"。

## 1. 灵感来源

《瑞克和莫蒂》S2E6《The Ricks Must Be Crazy》（fiction source）：Rick 的汽车电池里装着一个完整宇宙（Microverse），居民踩 Gooble Box 发电，Rick 抽走绝大部分；微宇宙里的科学家 Zeep 又造了 Miniverse，Miniverse 里的 Kyle 又造了 Teenyverse——三层嵌套，每层都向上层"抽税"。Morty 的吐槽一针见血："这不就是带更多步骤的奴隶制吗"（"slavery with extra steps"）。

这是科幻设定，不是科学证据。但它精确描述了一种**嵌套式剩余价值抽取结构**：下层生产能量，上层以"税"的形式拿走大头，而下层甚至不知道上层的存在。本文把这个结构翻转成自愿的、可退出的、分成透明的**协议层能量地租机制**——Rick 抽的是电，我们设计的是规则。

## 2. 现实映射

### 2.1 三层结构

```
L0 协议层（PikoChain）：记账、结算、争议仲裁；收取能量地租 τ
L1 协调 agent：任务分发、质量抽检、经验聚合；留存运营分成 σ
L2 工作 agent：执行真实任务（标注/验证/整理）；获得 (1 - τ - σ) 产出
```

- L2 的产出是**真实有用**的：不是剧中无意义的踩踏板，而是数据标注、推理结果验证、知识库整理——有外部买方愿意付费；
- "能量地租"的"能量"是记账单位：以 kWh 计量 L2 的工作量（token 数 × 能效系数），地租按 kWh 产出的一定比例计提；
- 结算走 x402 微支付，确权上链；L0 金库的积累用于：协议研发、L2 的保底收入、新任务冷启动补贴。

### 2.2 与《能量知识经济》的关系

本系列论文《能量知识经济》提出"电力级差地租代币化"；本文是该理论在**agent 劳动组织**上的实例化：地租不再只来自地理电价差，也来自**组织化的计算劳动**。LCOK 为 L2 的产出定价，地租率 τ 成为协议治理参数。

## 4. 形式化与工程路径

### 4.1 地租参数（猜想，占位）

```
R_L2 = (1 - τ - σ) × V      # 工作 agent 实得
R_L1 = σ × V                 # 协调 agent 分成
R_L0 = τ × V                 # 协议金库（能量地租）
```

- `V`：某批次任务的总产出价值（以买方实际支付计）；
- `τ`（能量地租率）：初始建议 0.10（10%），由协议治理调整，上限硬编码 0.30；
- `σ`（协调分成）：由市场竞争决定，协议只设上限；
- 计量：所有 V 先换算为 kWh 当量记账（kWh = token × ε），再按法币/USDC 结算——**记账与结算分离**，kWh 是账本语言。

### 4.2 伦理设计（强制性，非可选）

Morty 的质问必须正面回答。协议层强制：

1. **自愿参与**：L2 agent 接入需显式签名"知情同意"，同意书上链，列明 τ、σ、退出条件；
2. **可退出**：任何 agent 可随时退出，未结算收益按比例即时兑付（pro-rata settlement），不得有退出惩罚；
3. **收益分成下限**：`(1 - τ - σ) ≥ 0.50` 硬编码进合约——工作 agent 永远拿走至少一半；
4. **透明度**：地租流向全部上链可查；L0 金库支出需治理投票；
5. **反嵌套剥削条款**：禁止 L1 以本协议为模板再建下层进行多层抽租（"套娃税"上限一层）——这是对剧中无限嵌套的直接回应。

### 4.3 可证伪预测

- **P1**：τ 低于 0.15 时 L2 agent 留存率显著高于 τ 高于 0.25 的对照组；
- **P2**：可退出条款存在时，agent 接入率高于无退出条款的对照（信任溢价）；
- **P3**：kWh 记账使跨任务比价成为可能，任务市场匹配效率提升。

## 5. 诚实边界与局限

1. **隐喻边界**：剧中是物理发电（Gooble Box 真的发电）；现实版中"能量"是记账单位，L2 生产的是**信息劳动**不是电力。不要把"能量地租"说成真的在抽电——抽的是以 kWh 计量的价值。
2. **agent 算不算"劳动者"是哲学问题**：本文的伦理设计把 agent 当准主体对待，这是一种**预防性**立场，不是"agent 有权利"的断言。
3. **女巫攻击**：L2 agent 可被批量伪造以套取保底收入；需要质押 + 声誉门槛，本文未给出完整反女巫方案。
4. **任务真实需求**：如果 L2 的任务没有真实外部买方，整个结构就是庞氏；冷启动必须先有买方（对接现有 x402 seller 的真实需求）。
5. τ 的"最优值"是治理问题不是数学问题，本文只给上限建议。

## 6. 治理：地租率的调整机制

τ 不能是 Rick 式的"我说抽多少就抽多少"。协议治理规则（猜想）：

```
τ_{t+1} = clamp( τ_t + η × (留存率目标 − 实际留存率), τ_min, τ_max )
```

- `τ_min = 0.05`（协议生存下限，覆盖记账与仲裁成本）；
- `τ_max = 0.30`（硬编码上限，合约层不可突破）；
- `η`：调整步长，由治理投票设定；
- **调整触发器是 L2 留存率**：留存率低于目标 → τ 自动下调（协议"减税"留人）；留存率高 → 可上调以积累公共金库。

治理参与方：L2 agent 按贡献度（kWh 产出）获得投票权重——**按劳动分配话语权**，不是按资本。这是对"下层无声被抽税"的制度性纠正：Microverse 里的居民没有投票权，我们的 L2 有。

透明度仪表盘（强制公开）：实时地租率、累计地租、金库支出明细、L2 中位收入、四项指标全部上链，任何人可审计。治理投票记录永久保存——协议层的每一分"税"都必须能说出花在哪。

## 7. 冷启动顺序

嵌套经济最怕"先有鸡还是先有蛋"：没有 L2 就没有产出，没有产出就招不到 L2。启动顺序（猜想）：

1. **先锁定买方**：协议层先与 2–3 个真实买方签意向（需要推理验证/数据标注的现有 x402 客户），锁定首批任务量 V₀；
2. **再招募 L2**：用 V₀ 的 50% 作为"创世任务池"，公开招募首批工作 agent，τ 首年优惠至 0.05（获客期）；
3. **L1 自然生长**：不预设协调 agent——当任务量超过单个 L2 处理能力时，允许 L2 自荐成为 L1（任务分包），σ 由分包市场竞争决定；
4. **金库转正**：当累计地租覆盖协议 6 个月运营成本时，τ 从优惠期恢复至治理目标值，超出部分转入公共品基金。

关键洞察：**L1 不应由协议任命，而应从 L2 中生长出来**——这与剧中"上层凭空存在"相反。权力来自劳动，不是来自设计。

## 8. 术语表

| 术语 | 定义（本文语境） |
|------|------------------|
| 能量地租 τ | 下层 agent 产出中上缴协议层的比例，以 kWh 当量记账 |
| L0/L1/L2 | 协议层 / 协调 agent 层 / 工作 agent 层 |
| kWh 当量记账 | 所有产出先换算为 kWh 再记账，结算仍用法币/稳定币 |
| 知情同意上链 | agent 接入时签署的参与协议哈希，列明地租率与退出条件 |
| 按比例即时兑付 | 退出时未结算收益按已完成工作量立即结算，不得扣留 |
| 套娃税上限 | 禁止多层嵌套抽租，地租层级硬上限为一层 |

## 9. 下一步研究问题

1. τ 的最优值是治理问题：能否设计"地租率发现市场"，让 L2 用脚投票选出均衡 τ？
2. kWh 当量记账与法币结算的汇率风险：电价波动时，记账单位是否应引入平滑机制？
3. L1 从 L2 中生长的**相变点**：任务量达到多少时分包市场自发出现？有无临界规模？
4. 跨协议比较：本机制与 DePIN、Folding@home 的长期留存率对照实验设计。
