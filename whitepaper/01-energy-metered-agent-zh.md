# 自带能量表的 Agent：x402 报价中的 kWh 成本公示

## Energy-Metered Agents: kWh Cost Disclosure in x402 Quotes

## 摘要

AI agent 每次提供服务都应在其 x402 报价中公示本次调用的 kWh 能量成本估计（token 数 × 模型能效系数 ＋ 工具调用能耗）。买方看到的不再只是 token 单价，而是"这份答案花了多少度电"——让能量成本从后台黑箱变成交易界面的显性字段。

---

## 1. 灵感来源

《瑞克和莫蒂》S1E9《Something Ricked This Way Comes》（fiction source）：Rick 随手造了一个递黄油机器人，机器人得知自己的人生目标就是"递黄油"后陷入存在主义危机："Oh my god."

这是一个科幻喜剧设定，不是科学证据。但它提出了一个真实问题：**如果每个 agent 都知道自己每次行动的能量成本，agent 经济会变成什么样？** 现实的 agent 今天对"递一次黄油花了多少电"一无所知——成本由运营方承担，agent 只管执行。本文主张把能量计量内置进 agent，把"存在主义危机"变成一句会计问题："我递这次黄油，值不值 0.001 度电？"

---

## 2. 现实映射

### 2.1 机制设计

在 x402 支付协议的报价（402 Payment Required）响应中，增加能量披露字段：

```json
{
  "price_usdc": "0.05",
  "energy": {
    "kwh_estimate": 0.00042,
    "method": "token-count × model-efficiency",
    "model_efficiency_kwh_per_mtok": 0.35,
    "tool_calls_kwh": 0.00002,
    "methodology_version": "em-0.1"
  }
}
```

- 买方 agent 在比价时同时看到价格和能耗，可以做"性价比 ÷ 能耗"的二维选择；
- 卖方 agent 无法再把低效模型伪装成高效服务——能量成本是物理量，难以长期造假；
- 与"能量平价"指数（TEPI）对接：kWh 成本 × 当地电价 = 能量公允价，形成独立于法币报价的第二价格锚。

### 2.2 与现有工作的关系

- 本系列论文《能量本位的机器原生经济》提出 kWh 记账层；本文是该记账层落到**单次交易**的工程实现。
- LCOK（知识平准化成本）的分子 E_total 正需要这类实测数据 feeding。

## 3. 先行者核查现状

- **能量"测量"有先行者**：KAIST 2026 年研究测得 70B 参数模型的 agent 单次复杂查询耗电约 348Wh，约为普通聊天机器人的 136.5 倍（techxplore, 2026-07）；Hausfather 实测发现 agent 约 96% 的能量花在重读自己的上下文上。这些工作证明了"agent 很费电"这个事实。
- **但"agent 内置实时 kWh 计量、并在报价单中向买方公示能量成本"**：本轮公开检索（公开网络索引、arXiv，2026-09-28）**未找到实质先行者**。

## 4. 形式化与工程路径

### 4.1 kWh 估计公式（猜想，需实证校准）

```
E_quote = N_in × ε_in + N_out × ε_out + Σ_j E_tool(j)
```

- `N_in / N_out`：输入/输出 token 数（x402 网关可实测）；
- `ε_in / ε_out`：模型能效系数（kWh/token），由模型发布方声明、第三方抽测审计；
- `E_tool(j)`：第 j 次工具调用的能耗估计（搜索、代码执行、API 调用各有系数表）。

### 4.2 实施三步（PikoChain x402 栈）

1. **v0.1**：facilitator 在 402 报价中附加 `energy` 字段，ε 系数用公开基准表（先按模型家族给占位值，明确标注未审计）；
2. **v0.2**：引入"能效审计员"角色——随机抽查卖方的实际能耗声明，偏差超阈值扣声誉分（接 ERC-8004 声誉）；
3. **v0.3**：买方 agent 的采购策略支持"能量预算约束"（如"本次任务能耗上限 0.5 kWh"），协议自动过滤超标报价。

### 4.3 可证伪预测

- **P1**：公示能量成本后，高能效卖方的市场份额上升（买方用脚投票）；
- **P2**：同一任务下，agent 的能耗方差主要来自上下文重读长度，而非模型大小。

## 5. 诚实边界与局限

1. **ε 系数标准化是 hard problem**：不同硬件（H100 vs 4090）、不同量化、不同 batch 下同一模型的能效差数倍；v0.1 的占位系数只能算"示意"，不能当结算依据。
2. **自报数据的可信度**：卖方有低报能耗的动机（显得绿色高效）；需要审计与惩罚机制，本文只给出框架。
3. **工具调用能耗归因难**：一次搜索 API 背后是整个数据中心的能耗，分摊方法有主观性。
4. **剧中设定的边界**：黄油机器人的"存在主义危机"是喜剧效果；现实 agent 没有意识，"公示能耗"改变的是买方行为，不是 agent 的主观体验——不要把拟人化修辞写成机制结论。
5. 本公式未考虑 embodied carbon（硬件制造碳排放），只计运行能耗。

## 6. 买方行为模型（猜想）

能量公示改变的不是卖方，而是**买方的采购算法**。设买方 agent 面临 n 个报价 {(P_i, E_i)}：

```
选择规则：minimize  P_i + γ × E_i × p_kwh
```

- `γ`：买方的"绿色偏好系数"，由任务方设定；γ=0 退化为纯价格竞争；
- `p_kwh`：当地电价（来自 TEPI 或本地配置）；
- 当 γ 足够大时，市场出现**能效分层**：高能效卖方获得溢价，低效卖方被迫升级模型或降价——这是"公示"变成"减排"的传导链。

进一步，买方可设**能量预算约束**：`Σ E_i ≤ B`（本次任务总能耗上限）。协议层在 402 协商阶段即过滤超标报价，买方无需逐个试错。该约束对"夜间批量任务"（电价低时段）天然友好：agent 会学会**把高能耗任务调度到低电价时段**——需求侧响应（demand response）第一次出现在机器经济里。

## 7. 实施风险：博弈论视角（猜想）

公示机制面临三类博弈攻击，v0.1 必须预留对策：

1. **ε 虚报**：卖方虚报更低的模型能效系数。对策：ε 由模型发布方声明＋第三方抽测；同一模型家族的 ε 异常值触发审计；审计费用由败诉方承担。
2. **token 注水**：卖方故意输出冗长内容以摊薄"单位 token 能耗"观感。对策：E_quote 按**任务**计而非按 token 计展示——买方看到的是"完成这个任务花 0.42 Wh"，注水不改变任务总能耗。
3. **绿色洗白**：卖方购买"绿电证书"宣称零碳排放。对策：本文只公示 kWh（物理量），不公示碳排放——碳核算另行处理，不混入能量账本。

核心原则：**公示的是可测量的物理量，不是可解释的叙事**。kWh 难伪造，故事易伪造——账本只记前者。

## 8. 术语表

| 术语 | 定义（本文语境） |
|------|------------------|
| 能量公示 (energy disclosure) | 卖方在报价中向买方披露本次服务 kWh 成本估计的行为 |
| 模型能效系数 ε | 单位 token 的能耗，kWh/token，按输入/输出分别计量 |

## 9. 下一步研究问题

1. ε 系数的**硬件无关表示**是否存在？同一模型在 H100 与 4090 上的能效比是否稳定到可用单一系数加权？
2. 买方 γ（绿色偏好系数）的真实分布：agent 采购者是否真愿意为低能耗支付溢价，还是只看价格？
3. 能量公示与 LCOK 分子的对接：大规模公示数据能否反向校准各模型家族的 ε 基准表？
4. 监管视角：能量公示是否会成为未来 AI 服务合规（如欧盟 AI Act 能耗披露）的自愿先行实践？
